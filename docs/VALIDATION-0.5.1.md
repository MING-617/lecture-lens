# Lecture Lens 0.5.1 省电改动验证

测试日期：2026-10-05。设备：Apple M4，10 个逻辑 CPU，24 GB 内存，arm64，macOS 26.6.2。版本：0.5.1 / build 9。

## 改动和测量范围

- 原 Nemotron 模型、固定运行库、两条识别路径和 0.5 增强权重保持一致；模型仍使用两个 CPU 线程。
- 使用固定运行库已有的 provider 配置支持，将 `session.intra_op.allow_spinning` 和 `session.inter_op.allow_spinning` 设置为 0。[ONNX Runtime 线程文档](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)说明等待时的忙轮询会增加 CPU 与功耗。可选配置先由 Swift 严格核验，再传入原生解析器；损坏配置不会触发原生进程退出。
- 音量指示最多每 250ms 更新一次，状态没有变化时不重复发布；英文字幕回调仍立即处理。没有用 VAD 裁掉静音、弱声音或口音，没有增加课程选择或省电开关。
- 所有 CPU 对照使用同一个候选可执行文件、相同权重及词表。对照目录使用旧版默认 CPU 设置，候选目录使用等待休眠设置。串行输入实际节奏的音频，避免两个识别进程同时运行。调参语音使用 A/B/B/A 顺序复测。
- CPU 对照包在更新版本元数据前构建，报告中的版本号仍为 0.5.0；识别及界面代码已含本次改动。验收后更新元数据，正式 0.5.1 包另作签名与生产路径核验。
- CPU 用时是进程 user + system 时间，测量从模型就绪到流结束、排队任务和最终回调处理完成及工作线程释放；不含模型初始化。它反映计算工作量，不是瓦数，也不是续航提升百分比。后台 Codex 仍运行，未单独测量 SwiftUI 刷新减少的功耗。
- 延迟保留所有大于 3 秒的值；正确拼写单独对齐参考文本，遗漏词仍计入错误。时间戳来自识别器估计，没有逐词声学标注或屏幕绘制测量。

## 独立真人英语

使用原先固定的 LibriSpeech test-clean 40 条录音、10 位说话者、349.905 秒、824 个参考词；输入选择和校验和不变，完整录音和书籍文本留在本机。[0.5.0 真人结果](vocabulary-human-results.json)提供此前的准确率对照，不作为本次 CPU 节省对照。

新版最终字幕与 0.5.0 记录逐字一致：7 次替换、2 次漏词、0 次额外词，总计 9 个错误，词错误率仍为 1.092%。首次出现及最终正确拼写最大延迟均为 **1.160 秒**，超过 3 秒为 0，无运行错误。普通英文错误率没有上升。

已核对 0.5.0 ZIP 备份与更新前的安装包全部 20 个文件一致，并保存在仓库外。正式签名的 0.5.1 包另以真实节奏运行 141 词输入：零错误、最大延迟 0.784 秒、无超时，确认等待休眠设置已生效。实际旧版 benchmark JSON 可用新版 Swift 报告结构读取，新增 CPU 字段为空；新报告保留实际 CPU 数值。
