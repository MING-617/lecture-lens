# 0.4.0 验证记录

2026-10-01，Apple M4、24GB 内存、macOS 26.6.2。以下为该设备上的历史实测，不能代表所有 Mac 或教室的表现。

| 测试 | 词数 | 最大估计延迟 | 超过 3 秒 |
|---|---:|---:|---:|
| 最终安装版，约 25 秒自写英语按真实时间输入 | 68 | 0.767 秒 | 0 |
| 同一生产识别路径连续 2 小时，不重置模型 | 18,251 | 0.880 秒 | 0 |
| Mac 扬声器 → 内置麦克风，短段和补充术语句 | 77 | 0.79 秒 | 0 |

两小时测试包括转换器、Native 连续解码、VAD、主线程回调、字幕历史、术语匹配、延迟统计和完整字幕保存。最近 10,000 词 P95 约 0.775 秒；全程最大排队时间约 0.220 秒，最大单次处理时间约 0.215 秒，没有识别或积压错误。保存文件的 18,251 词与识别词数一致，画面历史保持 300 行。没有进行一天八小时实测。

实际麦克风测试自动显示 `shadow IT → 影子 IT` 及 PDF 第 14 页出处。保留了两组误听：`keeps a → pizza`、`Scrum → Sprum`；没有把原结果改成正确词来统计。确认停止后再次播放英语，界面及保存文件均未改变。

会话测试验证了确认前继续、取消继续、确认后关闭输入、保存末尾词、旧回调隔离、重启不覆盖旧文件，以及保存目录不可用时拒绝开始。4,001 词测试中，画面限于 300 行，文字文件仍保存全文。实际 SwiftUI 界面核对了按钮、快捷键、关闭和退出确认；回车默认继续听课。

核心断言检查了 321 个词条的匹配、上下文消歧、普通词过滤、已掌握词、分行与历史上限、真实迟到值不截断、全程最大值不因样本裁剪消失，以及讲话停顿与音频输入中断的区别。真实 worker 的 20 秒突发输入会被限流，只报错一次，队列在 3 秒内排空。

估计延迟使用模型词片时间戳加约 80ms 的近似词结束时间，到首次完整拼写送达主线程；最后一词在下一词到来或停止时计入。老师停顿不等于处理延迟。遗漏词不计入统计，词片时间戳不是独立声学真值，未测量 compositor 绘制时间。教室后排收音尚未验证。测试字幕、音频及包含个人路径的原始报告不纳入仓库。
