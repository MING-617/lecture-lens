# Lecture Lens 0.5.4 长课程开销与内存验证

测试日期：2026-10-06。Apple M4 / Mac16,1，4 个性能核心、6 个能效核心，24 GB，macOS 26.6.2，接电。模型、两条识别路径、0.5 专业词权重、两线程、background QoS 和 1.6 秒修订窗口均与 0.5.3 相同。没有新增功能或界面选项。

## 改动

1. **长课程每步开销不再增长。** 0.5.3 每次解码后都会把整节课的结果从头转换一遍：原生端重建全文、一份未使用的 JSON 和全部词片，识别路径每帧复制并比较整段历史，Swift 端再逐个解析全部词片。课越长，每一步越慢。0.5.4 的原生补丁在 1.6 秒修订窗口之外把已固定的词片移出识别路径，并新增两个 C 接口：查询已固定的词片数，以及只取这之后的结果。Swift 端只解析末尾，字幕文字随词增量维护。
2. **内存。** 可选 CPU 配置新增 `SessionConfig.mlas.disable_kleidiai=1`，改用 ONNX Runtime 的标准 MLAS 整数矩阵内核。KleidiAI 内核会额外保留一份重新打包的权重。
3. **静音检测按需运行。** VAD 只用于状态提示。字幕在 1 秒内仍有变化时，说明老师正在讲话，跳过 VAD；字幕停下 1 秒后恢复检测，所以“有人声但没有字幕”的提示时机不变。所有音频仍完整送入识别。
4. **界面刷新。** 音量、静音状态和耗时三种回调合并成一次主线程更新，每秒约 4 次（原来每段音频 3 次）。音量条单独刷新，不再带动整个窗口重绘。术语提示每次刷新只计算一次。窗口置顶和悬浮状态只在改变时设置。状态检查改为 0.5 秒一次，允许系统合并唤醒（判断阈值仍是 3 秒）。
5. **清理与小修复。** 删除不再使用的整句延迟统计、旧字幕合并路径、示例词表和 v1 偏好迁移、未用的语言参数和按课程过滤参数，以及不再被引用的 `Tests/Recalculate.swift`。字幕文件名的日期固定使用公历格式，不受系统日历设置影响。导入 TSV 时去掉字段两端的空格。原生结果缺少时间戳时保留已有字幕，不再清空。

## 长课程逐步开销（同一机器、串行、不按真实语速）

完整词表音频（619.6 秒）连续重复到 60 分钟，开启专业词增强，单次进程内模型不重置。“解码”是每 100 ms 输入的原生解码平均耗时；“取结果”是每次取结果并解析的平均耗时。

| 课程进度 | 0.5.3 解码 | 0.5.4 解码 | 0.5.3 取结果 | 0.5.4 取结果 |
| ---: | ---: | ---: | ---: | ---: |
| 5 分钟 | 17.99 ms | 17.57 ms | 0.51 ms | 0.05 ms |
| 30 分钟 | 22.40 ms | 17.56 ms | 4.98 ms | 0.05 ms |
| 60 分钟 | 27.27 ms | 16.98 ms | 10.54 ms | 0.05 ms |

0.5.3 的解码耗时在一小时内上涨 52%，取结果上涨约 20 倍；0.5.4 两项都保持不变。60 分钟的最终英文完全相同（SHA-256 `e05ef1c6…2067`，10,561 词）。没有实际测量两小时，但 0.5.3 的增长近似线性，课程越长，节省越多。

## 内存（每段测试音频完整跑一遍，只改内核开关）

| 测试音频 | 默认内核内存 | 标准内核内存 | 字幕 |
| --- | ---: | ---: | --- |
| 真人 349.9 秒 | 1423 MB | 803 MB | 相同 |
| 完整词表 619.6 秒 | 1526 MB | 864 MB | 相同 |
| 另外 8 段（语音、噪声、长停顿、静音） | 1383–1418 MB | 766–796 MB | 全部相同 |

载入模型时的峰值从约 1.9 GB 降到约 1.2 GB。10 段音频的总 CPU 能量分别为 1348.3 J 和 1348.2 J，没有差别。也试过关闭权重预打包（内存约 0.83 GB，但 CPU 能量多 64%）和关闭内存池／内存规划（几乎没有变化），都没有采用。

## 真实语速对照（已安装 0.5.3 应用与 0.5.4 候选应用交替）

| 输入 | 0.5.3 CPU 能量 | 0.5.4 CPU 能量 | 最大延迟（旧／新） | 字幕 |
| --- | ---: | ---: | ---: | --- |
| 60.6 秒语音，两轮 | 6.75 J、6.97 J | 8.21 J、6.64 J | 1.105 秒／1.054 秒 | 相同 |
| 真人 349.9 秒 | 38.50 J | 38.48 J | 1.380 秒／1.388 秒 | 相同 |

这些输入都很短，还看不出长课程的增长，只用来确认没有变慢、字幕和延迟都没有变化。新版的第一轮较高，第二轮与旧版相当；单次差异在正常波动范围内。没有超过 3 秒的延迟，也没有运行错误。

## 20 分钟真实语速连续检查（0.5.4 候选应用的生产路径）

使用 `Tests/LongRunTests.swift`：同一音频转换、连续解码、VAD、主线程回调、字幕历史、延迟统计、术语匹配和文件写入，完整词表音频按原速连续送入 1,200 秒，模型不重置。识别 3,518 词；最大首次显示延迟 1.259 秒，最大修订后延迟 1.116 秒，没有超过 3 秒的延迟；最大排队 0.666 秒，最大单次处理 0.631 秒；没有运行错误。自动保存全文与最终词序列一致，导出与保存文件一致。运行中内存保持在 739–743 MB，峰值 969 MB（0.5.3 两小时测试中分别为 1384–1435 MB 和 1701 MB）。

## 回归测试

`./Scripts/test.sh` 全部通过，新增两项检查：3,000 次随机修订中，只解析末尾的结果与完整重新解析逐次一致，增量维护的文字与逐词拼接一致；安装包自带的 CPU 配置被接受，顺序错误的配置会安全回退。此前 7,710 个 0.5.3 识别事件中，原生全文与逐词空格拼接全部一致，所以改由 Swift 维护文字不会改变字幕。

## 限制

测的是系统归因的进程 CPU 能量和耗时，不是整机电池放电。长课程对照不按真实语速，衡量的是每一步的处理成本。这次没有重新做麦克风、教室收音或两小时真实语速的测试。界面刷新的改动没有单独测功耗，只确认了构建通过和逻辑测试。
